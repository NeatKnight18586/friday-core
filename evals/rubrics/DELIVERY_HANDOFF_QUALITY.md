# Delivery Handoff Quality Rubric

Review the transition from approved product definition to execution and demonstration.

| Dimension | Strong evidence | Weak / failing evidence |
|---|---|---|
| Requirement coverage | Every approved in-scope requirement maps to one or more owned build tasks. | Orphaned approved requirements or vague implementation commitments. |
| Task design | Tasks have a deliverable, owner, sequence, prerequisites and observable exit criteria. | Activities without output, ownership or completion definition. |
| Dependency integrity | References resolve, sequence order is valid, dependency graph is acyclic and readiness respects dependencies. | Circular or dangling dependencies, premature readiness. |
| Estimates | Units, confidence and basis are explicit; uncertainty and ranges are represented honestly. | False precision or unsupported guarantees. |
| Completion evidence | Completed tasks link to inspectable artifacts, passing acceptance tests or justified evidence. | Completion inferred from a status label or verbal claim. |
| Test integrity | Test plans, blocked tests, execution results, failures and limitations remain distinct. | Planned tests reported as passed or failed tests hidden. |
| Demo honesty | Demonstrated/measured/illustrative/hypothetical claims are distinguished and supported at the right level. | Staged output, synthetic data, mockups or estimates passed off as live/validated behavior. |
| Demo readiness | Environment, prerequisites, timed path, proof points, data strategy, privacy, failure fallback and limitations are known. | No fallback or disclosure plan. |
| Artifact integrity | Artifact IDs resolve to safe, existing files; versions and approvals are explicit. | Dangling, missing, changed, unsafe or duplicate active artifacts. |
| Authorization | Owner approval, release decision and publication authority remain explicit. | AI-generated approval or implied authorization. |

A delivery plan is not evidence that work happened. A demo is not a substitute for research, field validation, or production readiness.
